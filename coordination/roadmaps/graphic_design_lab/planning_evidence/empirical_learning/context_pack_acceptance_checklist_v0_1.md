# Assistant context-pack acceptance checklist

When the GDL empirical methodology becomes project-owned, verify the assistant context generator includes or references enough information for cold-start continuation.

A generated context pack should allow a fresh assistant to answer all of these without prior chat history:

- What is the strategic purpose of the GDL empirical lane?
- What are the two current assistant roles?
- What does GDL Intake Analyst own?
- What does Creator Assistant own?
- What is the current experiment chain?
- Why are expectations frozen before a run?
- Why are raw failed responses preserved?
- How are loader versions changed?
- What is the current active case?
- What is the current stage?
- Which loader version is active?
- What is the next action?
- Which findings are hypotheses versus promoted patterns?
- Where are detailed case/evidence files located?
- What remains draft/non-canonical?
- What is the strict System Blueprint boundary?

If these cannot be recovered, the assistant context projection is incomplete.
