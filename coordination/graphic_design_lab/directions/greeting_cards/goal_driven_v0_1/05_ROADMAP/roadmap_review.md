# Roadmap · operator summary

R0: **зупинити неаналізований write**, оглянути Git worktree GC16–GC17.2, скрипти та докази GC18. Не замінювати працюючий Builder без порівняння.

R1: сформувати одне канонічне продуктове визначення сторінок, зон і параметрів, мету, acceptance та контекстний каталог.

R2: перевірити Intake↔Creator, якість структурованого промпта, повторне доопрацювання й Handoff ZIP. Це основна ризикова частина AI workflow.

R3: поєднати стабільний PDF backend і native Illustrator Worker на спільному LayoutSpec; додати зрозумілу conditional діагностику. Не вимагати зараз повної оркестрації й cloud API.

R4: три різні наскрізні контрольні замовлення, без ручних виправлень проміжних артефактів, із операторським прийманням; відновлення клієнтського інтерфейсу з сервера операторською командою.

R5: лише після R4 — пакетний reusable tool audit/registry, потім v2 візуального каталогу логотипів, workflow constructor та failover.

Деталі всіх мікрокроків, залежностей та `acceptance_check` — у YAML поруч. Вони поки синтетичні й повинні бути звірені з реальною кодовою базою та історичними completion reports перед використанням як operational roadmap.
